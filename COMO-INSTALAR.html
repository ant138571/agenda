Agenda de Tarefas

Como colocar o aplicativo no ar e instalar no computador e no celular. Tempo total: cerca de 20 minutos, uma única vez.

O que tem nesta pasta

index.html, sw.js, manifest.webmanifest, icons/, vendor/O aplicativo. Envie todos juntos, mantendo as pastas.
supabase.sqlScript que cria o banco de dados da sincronização.
tarefas-iniciais.jsonBackup com as 7 tarefas do seu Microsoft To Do, para restaurar no app.

Sem os passos 1 e 3, o app já funciona, mas salva só no aparelho em que foi aberto. A sincronização é o que faz computador e celular mostrarem as mesmas tarefas.

1 Criar o banco de dados gratuito (Supabase)

  1. Acesse supabase.com e crie uma conta (pode entrar com o GitHub ou e-mail).
  2. Clique em New project. Dê um nome (ex.: agenda), crie uma senha do banco (guarde-a) e escolha a região South America (São Paulo). Plano Free.
  3. Quando o projeto estiver pronto, abra SQL Editor no menu lateral, clique em New query, cole todo o conteúdo do arquivo supabase.sql e clique em Run. Deve aparecer “Success”.
  4. Clique em Connect (topo da página) ou em Project Settings › API Keys e anote dois valores:
    • Project URL, algo como https://abcdxyz.supabase.co
    • a chave pública: anon ou publishable (começa com eyJ ou sb_publishable_). Nunca use a chave service_role/secret.
  5. Opcional, recomendado: em Authentication › Sign In / Providers › Email, desligue Confirm email. Assim você entra direto ao criar a conta, sem precisar confirmar pelo e-mail.
No plano gratuito, o Supabase pausa o projeto após 7 dias sem nenhum uso. Se você abrir a agenda pelo menos uma vez por semana, isso não acontece. Se pausar, nada se perde: entre no painel do Supabase e clique em Restore project. Enquanto isso, o app continua funcionando com a cópia local e envia as alterações quando o projeto voltar.

2 Colocar o aplicativo no ar (GitHub Pages, grátis)

  1. Crie uma conta em github.com.
  2. Clique em + › New repository. Nome: agenda. Marque Public e clique em Create repository.
  3. Na página do repositório, clique em uploading an existing file e arraste todo o conteúdo desta pasta (arquivos e as pastas icons e vendor). Clique em Commit changes.
  4. Vá em Settings › Pages. Em Source, escolha Deploy from a branch, branch main, pasta / (root), e clique em Save.
  5. Em 1 a 2 minutos o endereço aparece no topo dessa página: https://SEU-USUARIO.github.io/agenda/.

O código do app fica público, mas suas tarefas não: elas ficam no seu Supabase, protegidas pela sua senha. Alternativas equivalentes ao GitHub Pages: Netlify ou Cloudflare Pages (arrastar a pasta).

Se você desligou “Confirm email” no passo 1.5, pule isto. Caso contrário, no Supabase, em Authentication › URL Configuration, coloque esse endereço em Site URL, para o link de confirmação voltar ao app.

3 Ligar a sincronização

  1. Abra o endereço do app no computador. No menu lateral, clique em Sincronização e backup.
  2. Cole o Project URL e a chave pública e clique em Salvar servidor.
  3. Digite seu e-mail e uma senha e clique em Criar conta (na primeira vez). Depois, e em outros aparelhos, use Entrar.
  4. Para trazer as tarefas do To Do: no mesmo painel, Restaurar backup › escolha tarefas-iniciais.json. Para importar mais tarefas, use Importar lista de tarefas e cole uma por linha.

4 Instalar no computador e no celular

OndeComo
Windows (Chrome ou Edge)Abra o endereço e clique no ícone de instalar à direita da barra de endereço (ou menu › Aplicativos › Instalar). O app ganha ícone no menu Iniciar e abre em janela própria.
Android (Chrome)Menu ⋮ › Instalar app (ou Adicionar à tela inicial).
iPhone/iPad (Safari)Botão Compartilhar › Adicionar à Tela de Início.

Em cada aparelho, faça o passo 3 uma vez (servidor + Entrar).

Uso offline

Depois da primeira abertura com internet, o app abre e funciona sem conexão: criar, editar, concluir e excluir tarefas continua normal. As alterações ficam guardadas no aparelho e são enviadas automaticamente quando a internet volta. O status no topo do menu mostra “Offline · N alterações a enviar” ou “Sincronizado”.

Se o mesmo item for alterado em dois aparelhos enquanto ambos estão offline, vale a última alteração enviada.

Atualizar o aplicativo no futuro

Substitua os arquivos no repositório do GitHub (mesmo processo de upload). Ao trocar o index.html, mude também a linha const VERSION = "agenda-v1"; em sw.js (para agenda-v2 etc.), para os aparelhos baixarem a nova versão. Suas tarefas não são afetadas.
